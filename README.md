안전링크 (SafeLink)
실시간 악성 링크 정밀 분석과 다중 보안 기관 검증, 그리고 개인 위험도 기록 관리를 하나로 통합한 보안 웹 애플리케이션입니다.

1. 프로젝트 소개 및 기획 배경
일상적인 웹 서핑과 업무, 학습 과정에서 사용자는 이메일, 문자 메시지, 메신저 등을 통해 매일 수많은 인터넷 링크를 접합니다. 하지만 공격자들은 짧은 주소 뒤에 실제 목적지를 숨기는 단축 URL을 사용하거나, 유명한 포털 및 금융 사이트와 철자가 비슷한 가짜 도메인을 만들어 사용자의 클릭을 유도합니다.

기존의 단순 링크 검사 도구들은 몇 가지 분명한 한계를 가지고 있었습니다. 첫째, 단순히 안전하거나 위험하다는 단편적인 결과만 보여주기 때문에 일반 사용자 입장에서는 이 링크가 도대체 왜 위험한지 구체적인 이유를 이해하기 어려웠습니다. 둘째, 방금 개설된 최신 피싱 사이트는 아직 전 세계 백신 데이터베이스에 등록되지 않은 경우가 많아, 보안 엔진의 탐지 결과만으로는 위험을 놓칠 가능성이 있었습니다. 셋째, 과거에 이미 검사했던 링크인지 기록이 남지 않아 매번 같은 주소를 다시 검색하는 번거로움이 있었고, 사용자 본인이 느낀 위험도와 실제 보안 분석 결과를 비교해 볼 수도 없었습니다.

안전링크는 이러한 불편과 보안 공백을 해결하기 위해 개발된 웹 기반 악성 링크 검사 및 기록 관리 프로그램입니다. 전 세계 수십 개 보안 기관의 위협 데이터를 제공하는 VirusTotal API와 자체 설계한 URL 구조 및 암호화 점검 알고리즘을 결합해 입체적인 위험도를 계산하며, 모든 검사 이력을 SQLite 데이터베이스에 체계적으로 저장해 중복 검사를 막고 안전한 웹 환경을 구축하도록 돕습니다.

2. 전체 시스템 구성과 파일 역할
안전링크는 기능별 책임이 명확히 분리되도록 세 개의 핵심 파이썬 모듈과 데이터베이스 파일로 구성되어 있습니다.

먼저 화면 구성을 담당하는 app.py는 Streamlit 프레임워크를 기반으로 전체 웹 인터페이스를 구현합니다. 왼쪽 사이드바를 통해 실시간 링크 검사, 직접 링크 등록, 내 기록 조회 및 검색, 위험도 통계 및 요약이라는 네 가지 핵심 메뉴로 이동할 수 있으며, 사용자의 입력값을 일차적으로 확인하고 분석 결과를 위험도 카드, 네 가지 항목별 안전도 게이지, 데이터 표, 통계 막대 그래프로 시각화합니다.

보안 분석을 담당하는 api.py는 입력된 인터넷 주소의 형식을 검증하고 불필요한 공백이나 위험한 프로토콜을 걸러내는 전처리 작업을 수행합니다. 이어서 단축 URL의 실제 최종 도착 주소를 추적하고, 통신 암호화 상태와 도메인 사칭 여부를 자체 알고리즘으로 분석한 뒤, VirusTotal REST API v3와 통신해 보안 기관들의 판정 통계와 사이트 평판 정보를 받아 최종 위험도 점수를 산출합니다.

데이터 영구 저장을 담당하는 database.py는 SQLite 데이터베이스 파일인 safelink.db를 생성하고 관리합니다. 프로그램이 실행될 때 links 테이블이 없으면 자동으로 생성하며, 새로운 검사 결과 저장, 검사 대기 링크 등록, 전체 목록 조회, 키워드 검색, 체감 위험도 점수 수정, 개별 기록 삭제 기능을 안정적으로 처리합니다.

3. 주요 기능 상세 안내
첫 번째 메뉴인 실시간 링크 검사는 의심스러운 URL을 즉시 분석하는 핵심 기능입니다. 사용자가 링크 주소와 선택적인 유입 출처를 입력하고 검사 버튼을 누르면, 먼저 데이터베이스를 조회해 과거에 이미 검사하거나 등록한 적이 있는 주소인지 확인합니다. 이미 기록된 주소라면 기존 출처와 판정 결과를 상단 알림으로 먼저 안내해 불필요한 중복 검사를 줄여줍니다. 이후 실시간 보안 분석이 완료되면 1점부터 10점까지의 통합 위험도 점수와 안전, 주의, 위험 세 단계의 종합 판정 카드가 출력되며, 점수 산출 근거와 최종 도착 주소도 함께 확인할 수 있습니다. 결과 화면 하단에는 보안 기관 검증, 사이트 성격 및 평판, 보안 연결 및 암호화, 도메인 및 사칭 점검이라는 네 가지 세부 진단 항목이 0퍼센트에서 100퍼센트 사이의 안전도 게이지 바 형태로 표시됩니다. 사용자가 내 기록 저장 버튼을 누르면 이 모든 분석 결과가 데이터베이스에 저장되며, 초기 체감 위험도는 입력 없음 상태로 기록됩니다.

두 번째 메뉴인 직접 링크 등록은 당장 API 검사를 진행하기 어렵거나 나중에 한꺼번에 확인하고 싶은 의심 링크를 미리 기록해 두는 기능입니다. 링크 주소와 유입 출처를 입력해 등록하면 앞뒤 공백과 눈에 보이지 않는 제어 문자를 자동으로 정리한 뒤, 검사 상태는 대기 중으로, API 위험도는 미검사로, 체감 위험도는 입력 없음으로 저장합니다. 화면 아래쪽 표에서는 현재 검사 대기 중인 링크 목록만 따로 모아 바로 확인할 수 있습니다.

세 번째 메뉴인 내 기록 조회 및 검색은 누적된 모든 링크 이력을 관리하고 비교 분석하는 공간입니다. 상단 검색창에 URL 일부나 출처 키워드를 입력해 원하는 기록만 찾아볼 수 있으며, 검색어를 비워 둔 채 검색하면 전체 목록을 최신순으로 보여줍니다. 여기에 전체 보기, 안전, 주의, 위험, 대기 중 필터를 함께 적용해 조건별로 기록을 추려낼 수 있습니다. 특히 목록 표에서는 API가 분석한 실제 위험도와 사용자가 직접 매긴 체감 위험도의 차이를 자동으로 계산해 비교 분석 결과를 보여줍니다. 실제 API 위험도가 체감 위험도보다 3점 이상 높으면 사용자가 방심하기 쉬운 위험 링크라는 뜻의 실제 위험 높음으로 표시하고, 반대로 체감 위험도가 3점 이상 높으면 우려보다 안전으로, 점수 차이가 2점 이내면 판단 일치로 안내합니다. 또한 화면 하단의 관리 영역에서 특정 기록을 선택하면 슬라이더를 움직여 체감 위험도를 1점부터 10점 사이로 수정할 수 있고, 대기 중 상태인 링크는 그 자리에서 바로 실시간 검사를 실행해 결과를 갱신하거나 필요 없는 기록을 개별 삭제할 수 있습니다.

네 번째 메뉴인 위험도 통계 및 요약은 사용자가 지금까지 관리해 온 전체 링크의 보안 현황을 한눈에 파악하는 대시보드입니다. 화면 상단에는 전체 관리 링크 수와 안전, 주의, 위험, 검사 대기 중 건수가 요약 카드로 배치되어 있으며, 하단 왼쪽에는 위험 등급별 분포를 색상별 막대 그래프로 시각화해 보여주고, 오른쪽에는 이메일, 문자, 메신저, 직접 검사 등 유입 출처별 등록 건수를 집계해 제공합니다.

4. 위험도 체크 및 점수 산출 원리
안전링크의 위험도 분석 엔진은 외부 보안 API의 결과 하나에만 의존하지 않고, 총 다섯 단계에 걸친 다층 검증 과정을 통해 최종 점수를 도출합니다.

일단계는 URL 정규화 및 사전 보안 검증입니다. 사용자가 입력한 문자열에서 앞뒤 공백은 물론 복사 및 붙여넣기 과정에서 섞여 들어가는 눈에 보이지 않는 유니코드 특수 공백 문자를 제거하고, 지나치게 긴 비정상 입력을 막기 위해 최대 길이를 2,000자로 제한합니다. 만약 주소 앞에 http나 https가 생략되어 있다면 자동으로 https를 붙여 표준 웹 주소 형태로 보완합니다. 동시에 웹페이지가 아닌 자바스크립트 실행 코드나 로컬 파일 접근 프로토콜, 잘못된 포트 번호, 실제 인터넷에 존재하지 않는 예약 테스트 도메인을 걸러냅니다. 또한 내부 서버망을 노리는 비정상 요청을 막기 위해 도메인 대신 사설 IP나 로컬 루프백 주소가 입력된 경우 외부 API 호출 전에 즉시 차단하고 안내 메시지를 출력합니다.

이단계는 단축 URL 리다이렉트 추적 및 통신 암호화 점검입니다. 공격자들이 실제 악성 주소를 감추기 위해 자주 쓰는 주요 단축 URL 서비스 도메인 13종이 감지되면, 프로그램이 직접 연결 경로를 추적해 최종적으로 도달하는 실제 목적지 URL을 찾아냅니다. 그다음 연결 방식의 안전성을 평가합니다. 보안 인증서가 손상되어 중간자 공격 위험이 있는 경우나, 처음에는 암호화된 HTTPS로 접속했으나 리다이렉트 도중 암호화가 풀린 일반 HTTP로 전환되는 경우에는 위험 가산점 2점을 부여하고 암호화 항목의 안전도 게이지를 15퍼센트에서 20퍼센트 수준의 위험 단계로 낮춥니다. 암호화 없는 일반 HTTP 주소이거나 실제 주소를 숨긴 단축 URL인 경우에는 위험 가산점 1점과 주의 단계 게이지를 부여하며, 정상적인 HTTPS 암호화 연결이 유지되는 사이트는 가산점 없이 안전도 100퍼센트를 부여합니다.

삼단계는 도메인 구조 및 피싱 사칭 휴리스틱 분석입니다. 아직 보안 기관 데이터베이스에 등록되지 않은 신생 피싱 사이트를 잡아내기 위해 주소의 문자열 구조를 일곱 가지 기준으로 정밀 검사합니다. 먼저 국내외 주요 포털과 은행, 공공기관 등 공식 도메인 15종을 기준으로 철자 유사도를 비교합니다. 숫자 0을 알파벳 o로 바꾸거나 숫자 1을 알파벳 l로 바꾸는 식의 동형이의어 치환과 철자 한 글자 변형, 또는 공식 브랜드 이름 뒤에 하이픈을 붙여 정상 사이트처럼 위장한 사칭 도메인이 발견되면 가장 높은 위험 가산점인 4점을 부여합니다. 또한 주소 중간에 골뱅이 기호를 넣어 앞부분을 정상 도메인처럼 보이게 속이는 주소 우회 트릭이나, 도메인 이름 없이 숫자 IP 주소로 직접 접속하는 경우에는 각각 3점을 가산합니다. 국제화 도메인 변환 기호인 퓨니코드가 포함된 경우에는 2점을 가산하며, 일반 웹 포트가 아닌 비표준 포트 사용, 네 단계 이상의 과도한 하위 도메인 깊이, 그리고 비공식 도메인에 로그인이나 계정 인증 같은 민감한 피싱 유도 단어가 포함된 경우에는 각각 1점씩 위험 점수를 추가합니다.

사단계는 VirusTotal REST API v3를 통한 다중 보안 기관 검증입니다. 앞선 단계에서 확인된 최종 도착 URL을 표준 URL-Safe Base64 형식으로 인코딩해 VirusTotal 클라우드 서버에 조회를 요청합니다. 서버에 이미 분석 기록이 있다면 전 세계 보안 백신 및 위협 분석 기관들이 판정한 악성, 의심, 안전, 미탐지 건수와 함께 사이트 카테고리 분류 및 평판 점수를 즉시 받아옵니다. 만약 전 세계에서 처음 조회되는 신규 URL이라 서버에 분석 기록이 없는 경우에는 자동으로 신규 스캔 요청을 전송한 뒤, 발급받은 분석 작업 번호를 이용해 일정 간격으로 완료 여부를 확인하며 실시간 분석 결과를 수집합니다. 수집된 카테고리 정보에 피싱이나 악성코드 관련 분류가 포함되어 있으면 사이트 평판 항목을 위험 등급으로 판정하고, 위험 노출이나 스팸 등 경고성 분류가 있으면 주의 등급으로 분류합니다.

오단계는 기본 위험도와 기술 가산점을 결합한 최종 점수 계산입니다. 먼저 VirusTotal 보안 기관들의 탐지 결과를 바탕으로 기본 위험도 점수를 결정합니다. 악성으로 판정한 보안 기관이 다섯 곳 이상이면 기본 10점, 세 곳에서 네 곳이면 9점, 두 곳이면 8점, 한 곳이라도 악성으로 탐지했으면 기본 7점을 부여합니다. 악성 판정은 없지만 의심으로 표시한 기관이 있는 경우에는 세 곳 이상이면 기본 6점, 두 곳이면 5점, 한 곳이면 4점을 부여합니다. 악성과 의심 탐지가 모두 0건인 정상 사이트는 안전하다고 확인한 보안 기관 수에 따라 50곳 이상이면 기본 1점, 10곳에서 49곳 사이면 기본 2점, 10곳 미만인 신규 사이트는 기본 3점을 부여합니다. 이렇게 산출된 기본 위험도 점수에 이단계와 삼단계에서 계산한 암호화 및 도메인 구조 위험 가산점을 더한 뒤, 최종 점수가 1점에서 10점 범위를 벗어나지 않도록 보정합니다. 최종 합산 점수가 1점에서 3점이면 안심하고 접속할 수 있는 안전 등급으로, 4점에서 6점이면 발신자와 출처를 다시 확인해야 하는 주의 등급으로, 7점에서 10점이면 개인정보 유출과 악성코드 감염 위험이 큰 접속 금지 위험 등급으로 최종 판정합니다.

5. 데이터베이스 설계 및 안정성 확보
안전링크는 별도의 외부 서버 설치 없이도 데이터를 안전하게 보관할 수 있도록 SQLite3 기반의 safelink.db를 사용합니다. 내부의 links 테이블은 각 기록을 구분하는 고유 번호 id를 기본 키로 두고, 원본 입력 주소 url, 리다이렉트 추적 후 확인된 최종 주소 final_url, 유입 출처 source, 검사 진행 상태 status, API 산출 위험도 api_risk, 사용자 체감 위험도 user_risk, 보안 기관 탐지 요약 engine_summary, 네 가지 항목의 게이지 점수와 산출 근거를 담은 detail_json, 그리고 등록 및 검사 일시 created_at 컬럼으로 이루어져 있습니다.

웹 환경에서 여러 요청이 빠르게 이어질 때 발생할 수 있는 데이터베이스 잠금 오류를 막기 위해 WAL 저널 모드와 대기 시간 제한 설정을 적용했습니다. 또한 과거 버전에서 생성된 데이터베이스 파일과도 충돌 없이 작동하도록 실행 시 테이블 컬럼 구조를 자동으로 점검해 누락된 컬럼을 보완하며, 클라우드 배포 환경처럼 기본 폴더에 쓰기 권한이 제한된 경우에는 시스템 임시 디렉터리로 저장 경로를 자동 전환하도록 설계했습니다. 검색 기능에서는 퍼센트나 밑줄 같은 SQL 특수 문자가 검색어에 포함되어도 의도치 않은 전체 조회가 일어나지 않도록 이스케이프 처리를 적용했습니다.

6. 예외 처리 및 개발 중 문제 해결 기록
실제 사용자가 다양한 잘못된 입력이나 네트워크 불안정 상황을 겪더라도 프로그램이 강제 종료되지 않도록 전 구간에 예외 처리를 적용했습니다. 빈 칸이나 공백만 입력한 경우, 지원하지 않는 프로토콜이나 내부 IP를 입력한 경우, 인터넷 연결이 끊기거나 응답 시간이 초과된 경우, 그리고 무료 API의 분당 요청 한도를 초과한 경우 모두 상황에 맞는 명확한 한글 안내 메시지를 화면에 표시합니다. 또한 사용자가 입력한 URL이나 출처 문자열에 HTML 태그가 포함되어 있어도 화면 구조가 깨지거나 스크립트가 실행되지 않도록 모든 출력 텍스트에 HTML 이스케이프 처리를 적용했습니다.

개발과 배포 과정에서는 세 가지 주요 문제를 발견하고 해결했습니다. 첫째, 네 가지 안전도 게이지를 화면에 출력할 때 HTML 문자열 내부의 줄바꿈과 들여쓰기를 마크다운 파서가 코드 블록으로 오인해 태그 글자가 그대로 노출되는 문제가 있었습니다. 이를 해결하기 위해 들여쓰기를 제거한 단일 문자열 구조로 HTML 렌더링 코드를 재구성하여 깔끔한 게이지 패널을 완성했습니다. 둘째, 보안 기관 카테고리 데이터에 위험 노출을 뜻하는 elevated exposure 같은 경고 문구가 포함된 사이트가 일반 미분류 사이트로 잘못 분류되던 문제를 발견해, 위험 노출 키워드 분기 조건을 추가함으로써 주의 등급과 평판 안내가 정확히 표시되도록 개선했습니다. 셋째, 깃허브에 코드를 올리고 Streamlit Cloud로 배포했을 때 보조 모듈 버전 차이로 인해 AttributeError가 발생하며 화면이 멈추는 문제가 있었습니다. 이를 해결하기 위해 외부 모듈 함수에 의존하지 않고 파이썬 표준 html 라이브러리를 메인 파일에 직접 내장했으며, 구버전 데이터베이스 기록을 불러올 때도 키 오류가 발생하지 않도록 방어 코드를 보강해 모든 메뉴가 안정적으로 작동하도록 수정했습니다.

7. 향후 개선 계획
현재 안전링크는 단일 URL의 정밀 분석과 개인 이력 관리, 통계 시각화 기능을 안정적으로 제공하고 있습니다. 향후에는 여러 개의 의심 링크를 한 번에 입력하거나 텍스트 파일로 불러와 순차적으로 검사하는 다중 URL 일괄 스캔 기능과, 필터링된 검사 이력 및 위험도 비교 결과를 CSV 파일로 내려받는 보고서 내보내기 기능을 추가해 활용도를 더욱 높일 계획입니다.
